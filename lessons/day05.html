Module 1: Motivation

Every problem is a gift — without problems we would not grow.

— Anthony Robbins

In the professional world, especially in engineering, your value is directly proportional to the complexity of the problems you can solve. However, solving a problem is only half the battle; effectively communicating your problem-solving process to stakeholders is what truly distinguishes senior talent. Today, we focus on vocabulary, structures like conditional sentences, and clarity. Embrace problems as opportunities to showcase your resilience and clear thinking.

Stakeholder

/ˈsteɪkˌhəʊldə/Noun

Antonyms: Bystander, Outsider

Module 4: Phrasal Verbs

Work around

Find a way to overcome a problem without actually fixing its root cause.

Usage: Discussing temporary fixes.

  • Interview: We had to work around the API limitation.

Figure out

Understand or solve something.

Usage: Describing discovery.

  • Interview: I figured out the root cause of the memory leak.

Narrow down

Reduce the number of possibilities or choices.

Usage: Debugging process.

  • Interview: I narrowed down the issue to a specific module.

Zero in on

Direct all attention to one particular thing.

Usage: Focusing on the core issue.

  • Interview: We zeroed in on the database latency.

Weigh up

Carefully consider the pros and cons.

Usage: Decision making.

  • Interview: I weighed up the costs of both architectures.

Sort out

Resolve a problem or difficulty.

Usage: General problem solving.

  • Interview: I sorted out the merge conflicts.

Deal with

Take action to solve a problem.

Usage: Handling responsibilities.

  • Interview: I deal with legacy code daily.

Think through

Consider all the possible details of something.

Usage: Planning.

  • Interview: I like to think through the architecture before coding.

Come up with

Produce an idea or solution.

Usage: Innovation.

  • Interview: I came up with a caching strategy to fix it.

Try out

Test something to see if it works.

Usage: Experimentation.

  • Interview: We decided to try out a new deployment tool.

Module 6: Grammar - Conditional Sentences (Types 0, 1, 2)

Type 0: If + Present Simple, Present Simple. (General truths)
Type 1: If + Present Simple, Will + Base verb. (Real/Likely future)
Type 2: If + Past Simple, Would + Base verb. (Unreal/Hypothetical present/future)
TypeUsageInterview Example
0 (Zero)Facts, rules, general truthsIf the server goes down, the load balancer routes traffic elsewhere.
1 (First)Real possibilities in the futureIf we implement caching, the latency will drop by 40%.
2 (Second)Hypothetical situationsIf I were to approach this problem from scratch, I would use React.

Indian English Errors

Wrong: 'If I will find a bug, I will fix it.'
Correct: 'If I find a bug, I will fix it.'

Explanation: Do not use 'will' in the 'if' clause of Type 1.

Wrong: 'If I had money, I will buy it.'
Correct: 'If I had money, I would buy it.'

Explanation: Type 2 uses Past tense in the 'if' clause, and 'would' in the main clause.

Wrong: 'If suppose the server fails...'
Correct: 'If the server fails...' OR 'Suppose the server fails...'

Explanation: Using 'If' and 'Suppose' together is redundant.
